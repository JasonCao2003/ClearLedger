# 退款关联与金额口径校验

退款处理分成两件事：识别退款属于哪次支付，以及判断原支付导出的金额是否已扣除退款。自动关联不代表人工确认，也不自动修改交易金额。

## 使用

使用新版本桌面程序，在“待核实”打开“退款与原订单”，点击“扫描退款与净额”。总览查询也会在数据发生变化时重新校验，避免旧结果进入正式统计。

关联结果与金额口径可以分别筛选、分页并展开证据；点击交易可定位到明细。自动关联可以驳回、撤销驳回，重新扫描保留仍适用的人工驳回。

目前读取旧 HTML 迁移产生的 legacy_* 来源证据。纯手工交易没有订单标识，不参与自动匹配。普通手工交易仍采用原有人工确认口径。通用 CSV/XLSX 导入、手工指定多候选原订单及人工声明金额口径不在本次实现范围内。

## 匹配规则

- 渠道、标识类型和标识值必须一致。支付交易号与商户订单号属于不同命名空间。
- 明确“原交易单号 / 原支付单号 / 原商户单号”等引用优先；存在明确引用时，不用其他普通字段覆盖它。
- 商户订单号还须核对商户身份，已知本方账户不一致时不关联。
- 只有唯一原订单候选才建立自动关联；不会用同金额、商户相似、时间接近或截取订单号前缀替代身份依据。
- 退款必须有独立退款类型、成功状态和现金金额证据。失败、处理中、金额或性质已改、跨组重复争议均保留冲突。
- 退款日期不能早于原支付。跨币种证据不能混用。
- 多次部分退款保留为多个事件，按原订单累计校验；相同渠道标识、金额、时间的重复退款事件不会重复冲减。

## 金额语义

| 模式              | 必须满足的证据                                               | 统计方式                       |
| ----------------- | ------------------------------------------------------------ | ------------------------------ |
| gross：原支出     | 原实付或已归组的独立资金扣款等于导出金额，累计退款不超原实付 | 原月记原支出，退款月冲减       |
| net：已扣退款净额 | 导出金额 + 独立退款合计 = 已验证原实付                       | 还原原月原实付，再于退款月冲减 |
| unknown           | 缺少原实付、独立退款或明确净额证据                           | 暂停相关组正式统计             |
| conflict          | 证据不一致、超额退款、累计状态不符等                         | 暂停相关组正式统计             |

例如导出原订单金额 70 元、独立退款 30 元、原实付证据 100 元：1 月记支出 100 元，2 月记退款 30 元，两月净支出仍为 70 元。不能直接用 70 再减 30。

明确原实付字段支持“原支付金额 / 原实付金额 / 原交易实付金额”；净额字段支持“退款后金额 / 退款后实付金额 / 交易净额 / 净支出”。字段值仍需满足等式。普通“订单金额”不视为用户实付，“实付金额”与标价的差额也不视为退款。

当前独立扣款证据只采用已归组的工行银行支出，不把另一支付平台显示的金额直接当作原支付毛额；后续接入其他银行时需补充相应适配与验证。

微信原支出行的全额退款状态，需要与独立退款总额和原行金额一致；部分退款状态只校验累计数，单凭累计数一致不能证明原支付毛额。支付宝、京东、美团的退款状态不直接声明毛额或净额。只有状态、没有独立流水时，不生成推测退款。

全额净额为零但没有可映射的正金额原交易时，保留来源证据和未匹配结果，不伪造 0.01 元交易。

## 正式统计与编辑

来源退款关联组只有在原交易和全部关联退款均已确认、金额口径通过、版本一致时计入。未通过时，pendingCount 包括被关联校验暂停的已确认记录，并不只等于数据库中 review_status=pending 的笔数。

金额、日期、性质或作废变化使关系失效，下一次扫描重新验证；只修改备注、分类或确认状态会刷新关系版本。原始来源始终不变。已验证的净额只在统计中还原毛额，不覆盖明细中的导出金额。

扫描以事务更新关系、语义和退款审计，不改变交易金额或人工确认状态。重复扫描相同证据不重复增加审计。统计缓存使用连接 data_version、交易笔数及 revision 合计，在外部导入或本地编辑后失效。

## 数据升级

schema v3 新增 refund_links、refund_semantics 和 refund_audit_events。首次打开旧数据库时先用 SQLite backup API 备份，再事务迁移。旧 schema v2 程序不能写入升级后的数据库，请使用新编译版本；不要手动改 user_version 降级。

HTML 迁移工具兼容 schema v2/v3；导入数据仍统一待核实。

## 规则依据与边界

- [微信支付退款介绍](https://pay.wechatpay.cn/doc/v3/merchant/4013071001)：存在优惠时，订单总额、用户实付与实际退款可能不同。
- [支付宝退款接口字段](https://developer.alibaba.com/docs/api.htm?apiId=1598&docType=4)：原订单引用和退款请求标识承担不同职责，多次退款需要区分退款事件。

这些接口资料不等于消费者 CSV/XLSX 的通用字段定义。应用依据当前导出行和关联凭证验证金额等式，不能验证的部分明确保留待核实。它不发起支付或真实退款。
